- The HTTP clients that carry a credential follow no redirect ([#420](https://github.com/mdastpak/Crypto-Exchange/issues/420), [#554](https://github.com/mdastpak/Crypto-Exchange/issues/554)): the market-data sources and venue connectors, SMS.ir, Kavenegar, Jibit, Sumsub, the TronGrid node, the TRON signer, and the unwrap of the signer's seed. Go's default policy sent a key in a custom header (`X-API-KEY`, `TRON-PRO-API-KEY`, `x-cg-pro-api-key`, `X-Vault-Token`) or in the URL to whatever host a redirect named, and `Authorization` to plain http. A provider that answers with a redirect now fails with `redirect refused`; set its new address in the configuration. The OFAC download, which carries no credential, follows redirects to any host over https only.
  - `internal/codestyle` fails on an `http.Client` literal without `CheckRedirect`; `internal/redirect` holds the two policies.
